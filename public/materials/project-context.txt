# Adaptive Learning Analytics Platform — архитектурный проект

Я объединил нашу концепцию в проект системы, которую можно реализовывать поэтапно, не останавливая действующие образовательные программы.

В основе будут пять принципов: единая модель образовательных данных, независимое версионирование материалов и учебных планов, автоматическое закрепление версии за студентом, проверяемая аналитика из Moodle/GitLab/Sheets и постепенная модернизация существующего AsciiDoc-плагина.

Два пилотных курса станут проверкой архитектуры: «Основы ИИ» — индивидуальный онлайн-курс с версиями HTML и результатами Moodle; Java Dual Training — групповая программа с разными назначениями, дедлайнами и GitLab MR.

Главное решение: не делать количество Moodle-активностей основой процента прохождения. Система будет рассчитывать прогресс по обязательствам, зафиксированным в индивидуальном учебном плане студента.

В архитектурный пакет также включаю требования к историческим данным, ручным миграциям между версиями, качеству сопоставления MR и воспроизводимости всех расчётов.

## Предлагаемая последовательность работы

1. Сначала визуализировать архитектуру

   Создать GitHub-репозиторий, загрузить содержимое ZIP и передать Codex файл `codex/IMPLEMENTATION_PROMPT.md`.

   Первый результат — интерактивный сайт со схемами, терминами, двумя моделями обучения, примерами версионирования и переноса прогресса.
2. Затем провести технический аудит Moodle и GitLab

   Выяснить, как плагин сохраняет оценки, какие данные реально доступны, как устроены HTML-сборки и насколько можно связать Java MR с Moodle assignments.
3. Построить первый работающий MVP

   Подключить данные двух пилотных курсов, сформировать учебные планы и рассчитывать прогресс студентов без изменения существующих курсов.
4. Добавить версии и миграции

   Автоматически закреплять релиз для новых студентов, выявлять устаревшие прохождения, моделировать перенос результатов и только после проверки включать изменение версии.
5. Развивать Content Platform

   Постепенно вынести HTML-интерактивности в самостоятельные версионированные компоненты с единым контрактом, сохраняя поддержку текущих AsciiDoc-сборок.

## Что особенно важно перед разработкой

Документация содержит целевую архитектуру, а не утверждение, что ваши существующие Moodle-плагины и GitLab-репозитории уже поддерживают все эти механизмы. Точки, требующие проверки на реальных системах, вынесены отдельно.

Например, возможности Moodle External Services и Events API позволяют построить часть интеграционного слоя, но фактическая доступность оценок, попыток и пользовательских событий зависит от вашей версии Moodle, настроек и плагина.&#x20;
