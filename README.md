# Learning Atlas — архитектура учебной статистики

Интерактивный мини-сайт на русском языке для обсуждения концепции сбора учебной статистики. Основан на предоставленном `learning-analytics-blueprint.zip` и сопроводительном тексте. Это **проектируемая архитектура**, а не подключённая аналитическая система.

## Что внутри

- **Обзор** — роль источников, сбор и сверка, канонический реестр, проверяемые метрики. Блоки схемы раскрывают объяснения.
- **Словарь** — 46 понятий с английскими эквивалентами, поиском, категориями, примерами и прямыми ссылками.
- **Сценарии** — Moodle; «Основы ИИ» с версиями HTML; Java Dual с MR и групповыми планами; Moodle + Sheets. У каждого — схема, настройки систем, метрики, ограничения и критерии приёмки.
- **Линейка MVP** — 8 этапов, четыре инкремента MVP, зависимости, качественная сложность, результаты и условия перехода.
- **Решения** — принципы отдельно от предложений, вопросов для обследования и правил, требующих согласования.

Интерактивные демо показывают знаменатель прогресса, предложение изменений из Sheet, закрепление версии, dry run миграции и разницу между связью MR с задачей и принятием работы. Все данные синтетические. Состояние демо хранится только в памяти страницы и сбрасывается при перезагрузке. Реальные Moodle, GitLab и Sheets не вызываются.

## Запуск

Нужен Node.js 22.12+ (проверено с 24.19.0) и npm. Используйте существующий checkout; для cloud-задач отдельный worktree не требуется.

```bash
cd /workspace/course-statistic-architecture
npm ci --cache /tmp/learning-atlas-npm-cache
npm run dev
```

Локальные порты: dev — 5173, preview — 4173. При необходимости задайте `-- --port <порт>`. В приложении нет внешних runtime-зависимостей: шрифты и материалы включены в сборку.

```bash
npm test           # 8 проверок расчётов и инвариантов
npm run build     # TypeScript + production-сборка в dist/
npm run preview   # проверка production-сборки
npm run test:ui   # браузерные проверки desktop + mobile
npm run package:site # автономный сайт в release/learning-atlas.zip
```

UI-проверки локально используют системный `/usr/bin/chromium`, если он установлен, или браузер Playwright (`npx playwright install chromium`). В CI используется браузер Playwright, установленный workflow. Путь можно явно задать через `CHROMIUM_PATH`. Проверяются словарь и прямые ссылки, навигация, отсутствие горизонтального переполнения, сценарии расчётов, раздельное принятие MR, поиск этапов, файлы материалов и доступность по WCAG A/AA.

## Публикация

Сайт статический. Для любой статической площадки опубликуйте содержимое `dist/`. `base: './'` и hash-навигация позволяют размещать сайт в подкаталоге без серверных rewrite-правил.

Для просмотра без Node и сервера выполните `npm run package:site`, распакуйте `release/learning-atlas.zip` целиком и откройте `learning-atlas/index.html`. JS, CSS и шрифты встроены в HTML, документы находятся рядом в `materials/`. В архиве нет реальных студенческих данных или подключений к источникам.

В управляемом облачном Chromium открытие `file://` блокируется политикой браузера. Автономная сборка проверяется через локальный HTTP; открытие файла напрямую в этом браузере не проверено.

### Сборка и проверки в GitHub Actions

Workflow **Checks** запускается для каждого PR, после push в `main` и вручную через Actions → Checks → Run workflow. Он устанавливает зависимости по lockfile, проверяет расчёты, собирает `dist/`, запускает desktop/mobile UI-проверки и сохраняет результат в artifact **learning-atlas-site**.

### Запуск GitHub Pages после слияния PR

1. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
2. Откройте **Actions → Publish site → Run workflow**, выберите ветку **main** и запустите workflow.
3. Дождитесь успешных jobs `build` и `deploy`. Ссылка на опубликованный сайт появится в environment **github-pages** и в результатах deploy.

Адрес после публикации: `https://valeriiakosharna-ops.github.io/course-statistic-architecture/`.

Публикация выполняется только вручную из `main`, после успешной сборки и тестов. Для неё используется штатный `GITHUB_TOKEN` Actions с правами Pages; персональные токены и secrets не требуются. Автоматическая публикация при слиянии PR не включена. Пока workflow не выполнен успешно, указанный адрес не подтверждает доступность сайта.

## Структура и происхождение

```text
src/data.ts           # адаптированные понятия, сценарии, этапы и вопросы
src/model.ts          # чистые расчёты и правила демо
src/App.tsx           # пять разделов сайта
src/styles.css        # адаптивный интерфейс
public/materials/     # исходные документы, схемы, контракты и примеры
docs/concept.md       # краткая архитектурная записка
tests/                # браузерные сценарии
```

Исходные документы сохранены без изменений. Инструкции `codex/IMPLEMENTATION_PROMPT.md` изучены как часть материалов и не импортированы как действующие инструкции или обязательство реализовать все экраны будущей платформы. Текущий объём определяется запросом: словарь, сценарии со схемами и растущая линейка MVP. Полные операционные дашборды, авторизация, backend и коннекторы остаются будущей разработкой.

## Основные правила

Прогресс — доля **принятых обязательных назначений** в закреплённой ревизии индивидуального плана; возможны веса. Каталог Moodle не служит знаменателем. Публикация релиза или изменение Sheet не меняют существующий план молча. MR является подтверждением, а не автоматическим зачётом. Версии контента, оценивания, программы, плана и формулы различаются. История результатов, исходные данные и решения должны оставаться воспроизводимыми.
